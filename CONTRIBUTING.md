# Contributing

Small, reproducible changes are welcome. Include a synthetic failing case, the
protection boundary it exercises, and the checks you ran. Keep real prompts,
credentials, browser profiles, and customer information out of issues and PRs.

Priorities are ancillary-request false positives, user-visible block feedback,
provider compatibility fixtures, and bounded file-upload handling. Open an issue
before a large architectural change. See SECURITY.md for sensitive reports.

English is the source language for the README, public console, and technical
documentation. Keep the five README translations aligned with the English scope
and caveats. Legacy experiments may retain Korean comments or UI text.
